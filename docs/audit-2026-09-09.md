**Live spec.** Found and saved: `docs/api/hevy-openapi.2026-09-09.json`, extracted from `options.swaggerDoc` inside `https://api.hevyapp.com/docs/swagger-ui-init.js`. OpenAPI 3.0.0, info version 0.0.1, same 14 paths and 22 operations as the chrisdoc mirror. No rate-limit documentation, no `maximum` on any `pageSize`, no webhook paths in either document.

**Spec diff, live vs mirror (semantic only).**

- `superset_id` everywhere in live; the mirror and your brief say `supersets_id`. The code already uses `superset_id`.
- `PUT /v1/routines/{id}` accepts nullable `folder_id` in live. The code strips it with a comment saying PUT rejects it. Needs a write test.
- `POST /v1/workouts` now declares required fields and `is_private` default false.
- `ExerciseTemplate.equipment` is now a typed enum ref.
- `Routine.exercises[].rest_seconds` is typed `string` in live (mirror: integer). Looks like a spec bug, verify on live data.
- Enum schemas use `type: "enum"`, which is invalid OpenAPI. openapi-typescript may need a preprocessing step.

**Spec vs code assumptions.**

- `ExerciseHistoryEntry` is flat, one row per set: `workout_id`, `workout_title`, `workout_start_time`, `weight_kg`, `reps`, `set_type`. The code types it as nested `{start_time, sets[]}`. `get-exercise-progression` calls `entry.sets.filter`, which would throw on the live shape. Highest-value bug candidate, pending live confirmation.
- `exercise_history` filters are ISO date-time in the spec; the tool tells the LLM to pass `YYYY-MM-DD`.
- Workout events are `{type:"updated", workout}` or `{type:"deleted", id, deleted_at}`. The code's `HevyWorkoutEvent` type has `created`, `occurred_at`, and a top-level `id`, none of which exist. Passes through as raw JSON today, so the MCP tool works but the client type is wrong.
- `Workout` has `routine_id` (missing from code) and no `is_private` in the response schema (present in code).
- `RoutineFolder` has `index` (missing from code).
- `POST /v1/exercise_templates` returns `{id}` only, with 403 on custom-exercise limit. `POST /v1/routines` has 403 on routine limit. The client swallows the Hevy `error` body and surfaces axios's generic "status code 400".
- `body_measurements` default pageSize is 10 in spec; code defaults to 5.

## Blocked

**Live probes.** `HEVY_API_KEY` is not in my shell environment and there is no `.env` in the repo, so every live call returned 401. The permission classifier blocked my search of config files for it, which I did not work around. Unverified as a result: pageSize maximums, the flat exercise_history shape, event ordering and deleted-event shape, date-only filters, rate-limit headers on 200 responses, and the webhook endpoint's real contract. To unblock, put `HEVY_API_KEY=...` in a repo `.env` (already gitignored) and say so. I have a read-only probe script ready.

## Decisions needed

1. **TypeScript 7.0.2 is the latest tag.** Take it, or pin 6.x/5.9 as the conservative choice for a published library? I recommend 5.9/6.x for the library builds until the ecosystem (openapi-typescript, tsdown, biome type-aware rules) declares 7 support, and record it in an ADR.
2. **Commit the 0.2.0 baseline first**, as one commit matching the published tarball, before any Phase 1 refactor. I recommend yes.
3. **Move the coaching prompt out of CLAUDE.md** into `prompts/COACH.md` (with CHATGPT.md and GEMINI.md), and make CLAUDE.md a normal dev-instructions file. Recommend yes, given who will read the repo.
4. **Keep or drop `http.ts`** in the 1.0 MCP package. It is the ChatGPT/Gemini path, but ships wildcard CORS and optional auth. Recommend keep, require the bearer token, drop wildcard CORS.
5. **Webhooks.** The route exists but is undocumented. Include in the client as an explicitly "undocumented, verified on date X" module, or leave out of 1.0? Recommend include only if the live probe confirms the shape.
6. **Dependencies to add** (asking per your rule): `openapi-typescript`, `@biomejs/biome`, `tsdown` (or `tsup`) for ESM+CJS, `@changesets/cli` or a plain CHANGELOG.md. Drop `axios` in favor of `fetch`. Recommend tsdown and a hand-maintained changelog.
