# Probes 2026-10-30

Observed while building routines on a real account, not a dedicated probe run. Custom exercises cannot be deleted through the API and count toward a per-account cap, so the create was not repeated.

| Call | Spec (2026-10-29) | Live |
|---|---|---|
| `POST /exercise_templates` (`Hand Gripper`, `reps_only`, `forearms`, `other`) | `200 { id: integer }` | Body is the new template's id as a bare string: `df0c88ea-ec73-4b81-b7be-552ae7db5586`. `batch-find-exercises "Hand Gripper"` returned the same id, and `POST /routines` accepted it as an `exercise_template_id`. |
| `PUT /routines/{id}` with `rest_seconds: 0` | integer, no stated minimum | Accepted on five routines and read back as `0`. |

Consequences:

- `exerciseTemplates.create()` resolves to that id. The `create-exercise-template` description said the returned id was not a template id (c70200d, from reading the spec; it was never probed).
- Hevy's help centre says the rest timer is set per exercise and starts when a set of that exercise is completed, and that a circuit's rest goes on its final exercise (https://help.hevyapp.com/hc/en-us/articles/36954623739415). Not probed; it matches a 2026-10-29 session that ran 65 min against a planned 50 because the user rested after both exercises of each superset. A superset therefore needs `rest_seconds: 0` on every exercise except the last, or the user rests between them. The `rest_seconds` tool description now says so.
