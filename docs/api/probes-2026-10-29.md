# Spec update, 2026-10-29

Snapshot `hevy-openapi.2026-10-29.json`, pulled from the `swaggerDoc` embedded in `https://api.hevyapp.com/docs/swagger-ui-init.js`. No new endpoints; the 22 documented paths are unchanged. No live writes were made for this update; the read probes below ran with the owner's key (Pro account). Diff against `hevy-openapi.2026-09-09.json`:

## Live read probes

| Request | Result |
|---|---|
| `GET /user/info` | `data` keys: `distance_unit, id, is_pro, name, url, username, weight_unit`. All four new fields present. |
| `GET /exercise_templates?pageSize=100` | `thumbnail_url` present on 100/100 templates, `null` on 4. Values are `https://pump-app.s3.eu-west-2.amazonaws.com/exercise-thumbnails/…jpg`. |
| `GET /routines/{id}` | Routine keys: `created_at, exercises, folder_id, id, title, updated_at`. **No `notes` key**, although `POST /routines` accepts `notes`. Exercise keys include `notes` and `rest_seconds` (`150`, integer). Set keys: `custom_metric, distance_meters, duration_seconds, index, rep_range, reps, type, weight_kg`. **No `rpe`**, matching the spec removal. |

Consequence: routine-level `notes` is write-only as far as the API shows; whether the app displays it is unverified. The `create-routine` and `update-routine` tool descriptions say so.

## Fixed in the spec (patches removed from the generator)

| Change | Was patched by |
|---|---|
| `Routine.exercises[].rest_seconds` is `integer`, nullable | probes-2026-09-09 §5 |
| `Workout.routine_id` nullable | probes-2026-09-09 §6 |
| `pageSize` carries `maximum` (10, or 100 for exercise templates) and defaults match | probes-2026-09-09 §1 |
| `POST /routines` and `PUT /routines/{id}` return `{ routine: Routine }` | probes-2026-09-09 §9 |
| Routine sets no longer declare `rpe` | probes-2026-09-09 §9 |

## New in the spec

| Change | Effect |
|---|---|
| `ExerciseTemplate.thumbnail_url` (string, nullable) | Verified live. Flows through the generated types. |
| `UserInfo.username`, `is_pro`, `weight_unit` (`kg`/`lbs`), `distance_unit` (`kilometers`/`miles`) | Verified live. Flow through the generated types; `get-user-info` description updated. |
| `POST /workouts` returns `{ workout: Workout[] }`, a single-element array | Client unwraps it. Not verified live (a probe would log a real workout); the client accepts a bare `Workout` too. |
| `POST /body_measurements` returns `201` with an empty body (was documented as `200`) | Already handled: empty bodies parse to `undefined`. |
| `POST /exercise_templates` can return `403 exceeds-custom-exercise-limit` | Mentioned in the `create-exercise-template` tool description. |
| `Workout.description`, `Workout.exercises[].notes`, `Routine.exercises[].notes` nullable | Types only. |

The undocumented `/v1/webhook-subscription` endpoint (probes-2026-09-09 §8) is still absent from the spec.
